### 1. NIT: Scope of Manifest Comparison in `config_diffs`
- **Citation:** [`benchmark/llm_objective_setting/conversation/chat_mtp_repro/repro.py`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp_repro/repro.py) (364 lines), lines 279–281:
  ```python
      for k in ('payload_example', 'prompt_texts', 'model_sha256', 'build_sha256', 'code_sha256', 'ids'):
          if a[k] != b[k]:
              why.append(f'{k} differs')
  ```
- **Detail:** `config_diffs` verifies `payload_example`, `prompt_texts`, `model_sha256`, `build_sha256`, `code_sha256`, and `ids`. It omits `imported_unused_sha256` and block constants (`block_s`, `deadline_s`, `gate_max_s`, `sample_s`). Because `code_sha256` locks all executed harness files and the constants are hardcoded within `repro.py`, this has no practical effect on comparison validity, but checking all manifest fields would be completely exhaustive.

### 2. NIT: Python Binary Resolution in Launcher Command
- **Citation:** [`benchmark/llm_objective_setting/conversation/chat_mtp_repro/oneshot.sh`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp_repro/oneshot.sh) (132 lines), line 126:
  ```bash
  env PYTHONUNBUFFERED=1 python -u "$R/repro.py" "$@" > >(tee -a "$CONSOLE") 2>&1 &
  ```
- **Detail:** `oneshot.sh` invokes `python`, relying on `PATH` resolution in native Termux (where `python` points to Python 3), whereas [`repro.py`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp_repro/repro.py) line 1 specifies `#!/data/data/com.termux/files/usr/bin/python`. Using the explicit path `/data/data/com.termux/files/usr/bin/python3` or `python3` would strictly match the test runner command format, though in standard native Termux `python` and `python3` point to the identical interpreter.

### 3. MINOR / NOTE: Dynamic Monkeypatching of Imported Module Functions
- **Citation:** [`benchmark/llm_objective_setting/conversation/chat_mtp_repro/repro.py`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp_repro/repro.py) (364 lines), line 72:
  ```python
  cm.command, cm.payload = command, payload  # run_block looks both up in chat_mtp at call time
  ```
- **Detail:** Reassigning `cm.command` and `cm.payload` cleanly diverts [`chat_mtp.run_block`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp/chat_mtp.py#L212) to the frozen command and payload without modifying [`chat_mtp.py`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp/chat_mtp.py) on disk. This was verified by offline test `test_run_block_spawns_and_posts_the_frozen_values` in [`test_repro.py`](file:///termux-home/review/vis3c/round3_copy/benchmark/llm_objective_setting/conversation/chat_mtp_repro/test_repro.py) (189 lines, lines 80–86), confirming that the replacement values are dispatched during execution.
