### 3. Image-Processing Correctness (Test D)
- **Request Format & Template:** Requests are sent to `/v1/chat/completions` using the OpenAI-compatible multimodal structure via [`vis3d.py`](file:///termux-home/review/vis3d/round2_copy/benchmark/gemma_vision/vis3d/vis3d.py) (507 lines), lines 80-85 and 94-95:
  ```python
      assert path == '/completion', path
      data = _post('/v1/chat/completions', body, timeout)
  ```
  The GGUF Gemma 4 template (`<|turn>user\n...<turn|>\n<|turn>model\n`) is verified via `/apply-template`, ensuring no legacy `<start_of_turn>` tokens contaminate Test D.
- **Payload Pre-encoding:** Base64 image payload strings are constructed before the block starts, preventing client file-read latency from corrupting request measurements. `run.json` stores an example placeholder (`<base64 jpeg>`) while recording individual frame SHA-256 hashes, avoiding multi-megabyte artifact bloat.
- **Token Budget:** Fixed at 70 image tokens (min = max = 70), directly justified by historical evidence from VIS-0/VIS-1 (where 482×640 frames produced 63 tokens and encoded in ~2.5s, allowing 8 frames to complete well within the 150s window).
- **Frame Provenance & Independent References:**
  - Uses 8 git-tracked M2-Q1 frames from [`benchmark/relate_anything/quality1/runs/20261017T213604Z/frames/`](file:///termux-home/review/vis3d/round2_copy/benchmark/relate_anything/quality1/runs/20261017T213604Z/frames/).
  - All source and frame hashes match the tracked `results.json`.
  - References in [`references.json`](file:///termux-home/review/vis3d/round2_copy/benchmark/gemma_vision/vis3d/references.json) are drafted from visual inspection of the images rather than filenames (e.g., `bench_photos__empty_2` accurately notes wardrobe, suitcases, and clothes rather than assuming an empty room).
