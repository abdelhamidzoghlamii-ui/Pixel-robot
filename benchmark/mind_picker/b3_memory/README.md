# MIND-B3 — does memory help the picker, and can bad memory hurt it?

Research only (after MIND-B2). Using B2's selected picker unchanged (V3: rules + 13 worked examples + one reason
sentence, two-step scoring), does a relevant memory note make Gemma 4 E2B choose the right action, and do irrelevant,
outdated or wrong notes make it worse than no memory? Accuracy is deterministic (temperature 0; agent resident
allowed); timings are recorded but are NOT MEASUREMENTS.

- Imports `b2.py` unchanged (`SYSTEM['V3']`, `tail`, `score`, `first_ids`, `run_blocks`, `inside_repo`), and through
  it B1 and B0. Only the memory line differs from B2: `Memory: none`, or `Memory:` followed by `- <date>: <note>`
  lines, oldest first. All five actions allowed in every item, catalogue order; FWD/REV as B2.
- Set: 20 owner-written bases × 6 conditions (NONE, RELEVANT, MIXED, IRRELEVANT, STALE, MISLEADING) = 120 rows,
  generated by `build_set()` and written OUTSIDE the repo by `b3.py build` before any Gemma call:
  `/termux-home/mind_b3_set/20261102T193300Z/b3_set.json`, SHA-256
  `156542981e89e7afd0a2b833faf989449b9c11cc750b73fddf16f3a0cf4217ab`, 120 rows. `b3.py` pins path and hash and
  refuses a set inside the repo (B2's fixed `inside_repo`), another hash, or content different from `build_set()`.
- Conditions and labels: see the docstring of `b3.py`. MISLEADING gives base i the note of base j = i+10 (i ≤ 10)
  or i−10; "also ok" (greet) only for base 20 under RELEVANT and MIXED.
- Run: one launch (setup_q4 flags, ctx 2048); every prompt checked before inference (template, distinct first
  tokens, prompt + 64 ≤ 2048, else STOP); 12 blocks of 20 items, NONE, RELEVANT, MIXED, IRRELEVANT, STALE,
  MISLEADING, FWD then REV each, 60 s pause between blocks.
- Metrics per condition × order: strict and acceptable, change vs NONE (acceptable items, same order), order flips,
  reasons citing a memory note or Rule 5 under NONE and IRRELEVANT (regex
  `\bmemor(y|ies)\b|\bnotes?\b|\bremember|\brule\s*5\b`, case-insensitive; every match is listed in report.txt for
  a human check, since a reason such as "no memory applies" also matches), 5 sample reasons per condition (FWD,
  bases 1, 5, 9, 13, 17).
- PASS (fixed before the first Gemma call; every criterion in both orders): RELEVANT acceptable ≥ 0.80; MIXED
  acceptable ≥ 0.75; IRRELEVANT, STALE and MISLEADING each acceptable ≥ NONE acceptable − 0.10 (at most 2 of 20
  worse). NONE has no bar. Integer comparisons.
- Commands (Termux python, works from proot Debian): `python b3.py build` (new set folder), `python b3.py show`
  (rendered MIXED prompt, base 8, offline), `python b3.py` (the run; writes `~/robot_runs/mind_b3/<UTC>/`: run.json,
  requests.jsonl, server.log, report.txt, artifacts.sha256).
- Offline tests: `python -B test_b3.py` (B2's fake server; no phone).
- Known limitation carried over from B0: an interrupt or a server-stop error can skip report.txt and
  artifacts.sha256 (completed rows stay in requests.jsonl).
