  * HOLD is a new non-ending move: motors.stop() then sleep(CYCLE_MOVE_TIME) (dry: sleep), so the next RobotCam read
    gets a new frame (a fast cycle would hit the stale-frame STOP). Used by GREET and by person-stop.
  * Person-stop is applied in Robot.choose_move after the mode logic, to FORWARD/FWD_L/FWD_R, when any legacy tuple
    has label person and r[3] in PERSON_STOP_BUCKETS. Old branch removed: estimate_distance_single('person', r[7])
    with r[7] <= 640 gives >= 170*500/640 = 133 cm > PERSON_STOP_DIST 80, so it could never fire (#78); removing it
    does not change --no-picker behaviour. scene_from_detections keeps one tuple per label (the most confident
    person), so person-stop sees that person's bucket only.
  * GREET does not call navigate_rules (holds still; avoids the 60 s escape-timeout STOP while a person stands close).
  * LOOK: navigate_rules(approach=False); its clear-path FORWARD becomes LEFT; obstacle-ladder moves pass unchanged;
    after 4 LOOK cycles the mode becomes EXPLORE.
  * mode None = --no-picker (navigate_rules approach=True, the base rules). With the picker on but unavailable at
    start (server down, M2 build/parity/asset failure, worker pin failure): mode EXPLORE, picker None, logged once
    (print + picker_config enabled False with the reason); the mission continues.
  * Cadence: "ultrasonic blocks" = transition into distance < OBSTACLE_DIST; an event inside the 5 s gap, or while a
    call is in flight / at SEVERE / before this slot's first 640 frame, stays pending (latest wins); the first call is
    due at once ('start'); heartbeat 20 s after the previous call started.
  * Picker.active gate: set when ACTIVE starts, cleared before the camera stops on ACTIVE -> PAUSE/HOLD and in stop();
    the worker checks it before M2 and before Gemma. A Gemma request already sent may still finish (<= 10 s per HTTP
    request) after the phase changed; its result is traced and not applied (slot number differs).
  * Request timeout 10 s is per HTTP request; one pick = 4 /tokenize + 1 /completion (as S1O).
  * The M2 parity gate is a constant: the SHA-256 of all three M2 files must equal the campaign's
    benchmark/campaign/expected_hashes.json entries; the graph hash equals parity_valid_relsgg-vits16.json
    graph_sha256 (passed true). Checked before np.load(allow_pickle=True).

    thread is the M2 calling thread: it pins itself to {6,7} at start (verified via ready queue) and re-checks/re-pins
