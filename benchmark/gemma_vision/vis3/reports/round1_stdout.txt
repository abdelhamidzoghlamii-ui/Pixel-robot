2. **P2 — Warm-phase throughput can be thermally confounded without the summary exposing its starting conditions.**

   `vis3_run.py:237`:
   ```python
        for name in ('cold', 'warm'):  # warm = immediate relaunch, files still in the page cache
   ```

   `vis3_run.py:383`:
   ```python
        gate_skin=(d.get('gate') or {}).get('skin'), phases=phase,
   ```

   The strengthened gate runs before the cold phase. Cold loading, initialization, and the first completion then heat the phone before the immediate warm launch. The summary’s start-skin comparison uses the earlier gate reading, rather than either phase’s actual launch temperature.

   Concrete scenario: OLD and NEW both pass at 31 °C, but their cold initialization leaves different temperatures or frequency caps. Warm throughput then differs partly because of that carry-over, while reported start-skin spread is zero.

   Gate the warm launch without dropping caches, and assess actual per-phase starting temperatures/caps. The existing CRITICAL and battery stops remain intact; this finding concerns comparison validity.

3. **P2 — A failed mapped-library check does not reject the block.**

   `vis3_run.py:248`:
   ```python
            phase['libs'] = mapped_libs(pid, build)
   ```

   `vis3_run.py:274`:

   A false `libs['ok']` is only reported later by summary checks. Execution continues through the measurement sequence and can receive `VALID`; aggregate configuration medians and NEW/OLD ratios still include it.

4. **P2 — The added intermediate shutdown races with the native memory sampler.**

   `vis3_run.py:198`:
   ```python
    v1.write(bridge/'target.json', dict(pid=None))
   ```

   `vis3_run.py:289`:
   ```python
            if [e for e in v1.rows(bridge/'errors.jsonl') if record['phase_start'] <= e['t'] <= record['stop_start']]:
   ```

   Clearing `target.json` does not acknowledge that an already-running monitor sample has finished. That sample may still hold the cold server PID when shutdown removes its `/proc` files. The reused monitor then records a sampling failure.

   Unlike VIS-2’s final shutdown, this cold-phase shutdown occurs inside the interval checked for sampling errors. A normal, clean exit can therefore invalidate the completed block, or transient error telemetry can abort the warm launch.

   Synchronize sampler detachment before stopping the server. Keep sampling failures during live measurement fatal. Add a test covering an in-flight sample during cold-to-warm shutdown.
